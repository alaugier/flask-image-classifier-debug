\section{Contexte et description de l'application}

\subsection{Objectif}

L'application est une interface web de \textbf{classification d'images satellite}
développée avec \gls{flask}. Elle permet à un utilisateur de soumettre une image et
d'obtenir une prédiction parmi quatre classes : \texttt{desert}, \texttt{forest},
\texttt{meadow} et \texttt{mountain}. L'inférence repose sur un modèle \gls{cnn}
pré-entraîné au format \gls{keras}. Un mécanisme de \gls{feedbackloop} utilisateur
alimente une base \gls{mongodb} pour permettre un futur ré-entraînement du modèle.

\subsection{Stack technique}

La stack complète est détaillée en Annexe~F. En résumé : backend Flask~3.1.2,
inférence Keras~3.11.3 + PyTorch CPU, persistance MongoDB Atlas, monitoring
Flask-MonitoringDashboard / \gls{sqlite}, 15 tests \texttt{unittest}, déploiement
\gls{gunicorn} + \gls{render} (\gls{paas}).

\section{Identification et correction des bugs \textnormal{\small\textcolor{RNCPred}{[C21]}}}

\begin{mdframed}[linewidth=1pt, linecolor=black!40, backgroundcolor=gray!4,
                 innertopmargin=8pt, innerbottommargin=8pt]
\small
\textbf{Synthèse des incidents — compétence C21}

\renewcommand{\arraystretch}{1.2}
\begin{tabularx}{\linewidth}{>{\bfseries\centering}p{1.2cm} >{\raggedright}p{3.6cm} >{\raggedright}p{2.8cm} >{\raggedright\arraybackslash}X}
    \toprule
    Bug & Symptôme & Type & Impact \\
    \midrule
    \#1 & \texttt{ValueError} : forme image incompatible & \textbf{Bloquant} & Application inutilisable ; erreur visible en logs \\
    \#2 & Prédictions identiques pour toutes images & \textbf{Silencieux} & Modèle dégradé ; aucune exception levée \\
    \bottomrule
\end{tabularx}
\end{mdframed}

Deux bugs indépendants ont été identifiés dans la fonction
\texttt{preprocess\_from\_pil()} de \texttt{app/app.py}. Le premier provoque
une erreur bloquante visible dans les logs ; le second est silencieux mais
tout aussi critique : il dégrade les prédictions sans lever d'exception.

% ----------------------------------------------------------
\subsection{Bug 1 --- Redimensionnement absent}

\subsubsection*{Symptôme}

Au lancement d'une prédiction sur une image uploadée, le serveur lève
l'exception suivante :

\begin{mdframed}[linecolor=red!60, linewidth=1pt, backgroundcolor=red!4,
                 innertopmargin=6pt, innerbottommargin=6pt]
\small\ttfamily
ValueError: Input 0 of layer "functional\_1" is incompatible with the layer:\\
expected shape=(None, 224, 224, 3), found shape=(1, 600, 600, 3)
\end{mdframed}

Le modèle Keras attend un tenseur d'entrée de forme \texttt{(None, 224, 224, 3)},
mais reçoit un tenseur \texttt{(1, 600, 600, 3)} correspondant à l'image originale
non redimensionnée.

\subsubsection*{Cause racine}

La fonction \texttt{preprocess\_from\_pil()} convertit l'image en RGB et la
normalise, mais \textbf{omet l'étape de redimensionnement}. L'image est donc
transmise au modèle à sa taille d'origine. Le code fautif est reproduit en
Annexe~A.

\subsubsection*{Correctif appliqué}

La correction s'effectue en deux étapes :

\begin{enumerate}[leftmargin=1.5cm]
    \item \textbf{Extraction dynamique des dimensions} attendues par le modèle
          lors du chargement, pour éviter toute valeur codée en dur :
          \begin{quote}\small\ttfamily
          model = keras.saving.load\_model(MODEL\_PATH, compile=False)\\
          MODEL\_HEIGHT, MODEL\_WIDTH = input\_shape[1], input\_shape[2]
          \end{quote}

    \item \textbf{Ajout du redimensionnement} via \texttt{Image.Resampling.LANCZOS}%
          ~\cite{Pillow} (filtre haute qualité, conforme aux recommandations
          Pillow $\geq$ 9.1).
\end{enumerate}

% ----------------------------------------------------------
\subsection{Bug 2 --- Double normalisation}

\subsubsection*{Symptôme}

Après correction du redimensionnement, les \textbf{prédictions sont identiques pour toutes
les images} : le modèle retourne systématiquement la même classe quelle que soit l'entrée.
Aucune exception n'est levée — le bug est entièrement \textbf{silencieux}.

\subsubsection*{Cause racine}

L'inspection via \texttt{model.layers[2].get\_config()} révèle une couche \texttt{Rescaling}
intégrée (\texttt{scale=1/255}). La fonction \texttt{preprocess\_from\_pil()} appliquait en
plus une division \texttt{/ 255.0}, soit une double normalisation : les pixels étaient divisés
par $255^2 = 65\,025$, produisant des valeurs $\approx 10^{-5}$. Le CNN recevait un signal
quasi nul, rendant toutes les activations uniformes et les prédictions dégénérées.

\subsubsection*{Correctif appliqué}

Suppression du \texttt{/ 255.0} dans \texttt{preprocess\_from\_pil()} : le tenseur est
désormais transmis dans $[0, 255]$, la couche \texttt{Rescaling} du modèle assurant seule
la normalisation. Le tableau de synthèse avant/après est disponible en Annexe~A.

\section{Validation par tests automatisés et pipeline CI/CD \textnormal{\small\textcolor{RNCPred}{[C21]}}}

\subsection{Stratégie de test}

La suite de tests est organisée en trois classes \texttt{unittest} :
\texttt{TestImageClassificationApp} couvre le flux de traitement des images
(validation des extensions, prétraitement, encodage, routes Flask, feedback) ;
\texttt{TestModelIntegration} vérifie la compatibilité entre le prétraitement
et l'interface du modèle ; \texttt{TestPreprocessNormalization} documente le
Bug~2 et valide son correctif. Les tests utilisent des \gls{mock}s pour simuler le
modèle Keras sans dépendre du fichier \texttt{.keras}.

Le test critique (\texttt{test\_preprocess\_from\_pil\_shape\_correction})
soumet une image synthétique 600$\times$600 et vérifie que la sortie a bien
la forme \texttt{(1, 224, 224, 3)} attendue par le modèle. Son code est
reproduit en Annexe~B.

\subsection{Résultats}

La suite CI passe \textbf{13/13 tests} en 18,4\,s sur Python~3.11 et~3.12 ;
2 tests d'intégration nécessitant le vrai modèle Keras sont skippés en CI
et s'exécutent localement lors de la démonstration. Le tableau détaillé par
catégorie est disponible en Annexe~G.

\subsection{Pipeline CI/CD}

Les tests sont intégrés dans un pipeline GitHub Actions~\cite{GitHubActions}
déclenché à chaque \texttt{push} sur la branche \texttt{main}. Le workflow
\texttt{.github/workflows/main.yml} exécute la suite en parallèle sur
Python~3.11 et~3.12, puis déclenche automatiquement le déploiement sur Render
si tous les tests passent (\texttt{needs: test}).

Deux adaptations techniques ont été nécessaires pour le CI :

\begin{enumerate}[leftmargin=1.5cm]
    \item \textbf{Installation explicite de \texttt{torch} CPU} avant
          \texttt{requirements.txt}, car Keras tente d'importer \texttt{torch}
          dès son initialisation :
          \begin{quote}\small\ttfamily
          pip install torch -{}-index-url https://download.pytorch.org/whl/cpu
          \end{quote}

    \item \textbf{Correction d'une assertion de test} incohérente avec le
          correctif Bug~2 : la vérification \texttt{valeurs~$\in$~[0,\,1]}
          a été remplacée par \texttt{valeurs~$\in$~[0,\,255]}, conformément
          à la délégation de la normalisation à la couche \texttt{Rescaling}.
\end{enumerate}

\subsection{Journalisation}

La journalisation est assurée par la bibliothèque standard \texttt{logging}~\cite{PythonLogging},
configurée avec deux \textit{handlers} : un fichier \texttt{app.log} et la
sortie console. Trois niveaux sont utilisés selon la gravité :
\texttt{logger.info()} pour l'état des services (ex.\ connexion MongoDB établie),
\texttt{logger.warning()} pour les situations dégradées sans arrêt du service
(ex.\ variable d'environnement absente), et \texttt{logger.error()} pour les
exceptions avec traceback (ex.\ erreur de connexion à Atlas).

\subsection{Alerting}

En production, un système d'alerte email est activé via \texttt{SMTPHandler}
(bibliothèque \texttt{logging.handlers}). Tout log de niveau \texttt{ERROR} ou
supérieur déclenche automatiquement l'envoi d'un email avec sujet
\og\texttt{ERREUR CRITIQUE --- App Classification}\fg{} vers l'adresse définie
dans la variable d'environnement \texttt{ALERT\_EMAIL\_RECIPIENT}. Les
credentials SMTP sont chargés depuis les variables d'environnement, jamais
codés en dur.

\subsection{Monitoring}

\texttt{Flask-MonitoringDashboard} est monté sur le endpoint \texttt{/dashboard}.
Il intercepte automatiquement chaque requête HTTP et enregistre dans une base
SQLite locale : le temps de réponse par endpoint, le code HTTP retourné,
l'utilisation horaire et la comparaison multi-version. Des scripts Python
dédiés (\texttt{monitoring/}) permettent d'extraire ces métriques pour une
analyse hors ligne (détection de régressions, pics de latence).

Un décorateur \texttt{@rate\_limit} assure le \gls{ratelimiting} de l'endpoint
\texttt{/predict} (10~req/min). Il est activé \textbf{uniquement en production}
via \texttt{FLASK\_ENV=production}, afin d'éviter les délais artificiels en
développement et de ne pas fausser les métriques du dashboard.
Le code correspondant est disponible en Annexe~H.

\section{Feedback loop, déploiement et perspectives \textnormal{\small\textcolor{RNCPred}{[C20, C21]}}}

\subsection{Versionnement et traçabilité des correctifs (C21)}

Les deux correctifs sont versionnés et accessibles sur le dépôt GitHub du projet :
\url{https://github.com/alaugier/flask-image-classifier-debug}

\subsection{Collecte des feedbacks}

Après chaque prédiction, l'utilisateur peut corriger le label via un appel
AJAX (\texttt{POST /feedback}). Le backend valide les champs reçus et insère
dans MongoDB Atlas un document structuré contenant l'image encodée en base64,
le label prédit avec sa confiance, le label corrigé par l'utilisateur,
un booléen \texttt{is\_correct} et la version du modèle ayant effectué
la prédiction.

\subsection{Déploiement sur Render}

L'application est déployée en continu sur Render (PaaS, plan gratuit) à l'adresse
\url{https://flask-image-classifier-debug.onrender.com}. Le déploiement est déclenché
\textbf{automatiquement} après validation des tests CI — aucune intervention manuelle
n'est requise. La build installe \texttt{torch} CPU en amont de \texttt{requirements.txt}
pour éviter le téléchargement de la version CUDA ($\approx$2~Go). Les variables sensibles
(\texttt{KERAS\_BACKEND}, \texttt{MONGO\_URI}, credentials SMTP) sont injectées via les
variables d'environnement Render, jamais stockées dans le dépôt. Des captures d'écran
du dashboard Render et des logs de déploiement sont disponibles en Annexes~D et~E.

\subsection{Stratégie de ré-entraînement sans fuite de données}

Un script \texttt{cron} quotidien déclenche un pipeline de ré-entraînement dès qu'un
seuil de feedbacks corrigés est atteint (ex.\ 100 observations). Le jeu de test initial
est \textbf{gelé} : seul l'ensemble d'entraînement est étendu avec les nouvelles données
MongoDB, garantissant la comparabilité des métriques entre versions et éliminant tout
risque de \gls{dataleakage} — approche \gls{mlops} standard.

\subsection*{A --- Fonction \texttt{preprocess\_from\_pil()} : avant et après correctifs}

\textbf{Version originale (deux bugs) :}

\begin{minted}[linenos=false]{python}
def preprocess_from_pil(pil_img: Image.Image) -> np.ndarray:
    img = pil_img.convert("RGB")
    # BUG 1 : pas de resize -> ValueError shape incompatible
    # BUG 2 : normalisation / 255.0 alors que le modele contient
    #         deja une couche Rescaling(1/255) -> double normalisation
    img_array = np.asarray(img, dtype=np.float32) / 255.0
    img_array = np.expand_dims(img_array, axis=0)
    return img_array
\end{minted}

\textbf{Version finale corrigée (deux correctifs intégrés) :}

\begin{minted}[linenos=false]{python}
# Chargement du modele et extraction dynamique des dimensions
model = keras.saving.load_model(MODEL_PATH, compile=False)
input_shape = model.input_shape       # ex. (None, 224, 224, 3)
MODEL_HEIGHT, MODEL_WIDTH = input_shape[1], input_shape[2]
# Note : model.layers[2] est une couche Rescaling(scale=1/255)
# => la normalisation est deja integree dans le modele


def preprocess_from_pil(pil_img: Image.Image) -> np.ndarray:
    """Prepare une image PIL pour l'inference Keras.

    Args:
        pil_img: Image PIL source, taille quelconque.

    Returns:
        np.ndarray de forme (1, MODEL_HEIGHT, MODEL_WIDTH, 3),
        dtype float32, valeurs dans [0, 255] -- la normalisation
        est deleguee a la couche Rescaling du modele.
    """
    # 1. Conversion RGB
    img = pil_img.convert("RGB")
    # 2. CORRECTIF 1 : redimensionnement aux dimensions du modele
    img = img.resize((MODEL_WIDTH, MODEL_HEIGHT),
                     Image.Resampling.LANCZOS)
    # 3. Conversion en array float32
    #    CORRECTIF 2 : suppression du / 255.0
    #    (la couche Rescaling du modele s'en charge)
    img_array = np.asarray(img, dtype=np.float32)
    # 4. Ajout de l'axe batch
    img_array = np.expand_dims(img_array, axis=0)
    return img_array   # shape : (1, 224, 224, 3), valeurs in [0, 255]
\end{minted}

class TestImageClassificationApp(unittest.TestCase):

    def test_preprocess_from_pil_shape_correction(self):
        """Test critique : le preprocessing doit redimensionner
        toute image a la forme attendue par le modele."""
        test_img = Image.new('RGB', (600, 600), color='blue')
        processed = preprocess_from_pil(test_img)

        expected_shape = (1, 224, 224, 3)
        self.assertEqual(
            processed.shape, expected_shape,
            f"Forme attendue {expected_shape}, obtenue {processed.shape}"
        )
        self.assertEqual(
            processed.dtype, np.float32,
            "Le type de donnees doit etre float32"
        )

    def test_preprocess_different_input_sizes(self):
        """Le preprocessing doit fonctionner pour toute taille d'entree."""
        test_sizes = [(100, 100), (300, 200), (800, 600), (1024, 768)]
        for width, height in test_sizes:
            with self.subTest(size=(width, height)):
                img = Image.new('RGB', (width, height), color='green')
                processed = preprocess_from_pil(img)
                self.assertEqual(
                    processed.shape, (1, 224, 224, 3),
                    f"Taille {width}x{height} mal redimensionnee"
                )
\end{minted}

\subsection*{C --- Tests unitaires : détection de la double normalisation}

\begin{minted}{python}
class TestPreprocessNormalization(unittest.TestCase):
    """Verifie que le preprocessing ne normalise pas les pixels,
    la couche Rescaling du modele s'en chargeant."""

    def test_no_manual_normalization(self):
        """Les valeurs de sortie doivent rester dans [0, 255], pas [0, 1]."""
        test_img = Image.new('RGB', (224, 224), color=(255, 255, 255))
        processed = preprocess_from_pil(test_img)

        # Si / 255.0 est present -> max ~= 1.0
        # Si absent (correct)   -> max ~= 255.0
        self.assertGreater(
            processed.max(), 1.0,
            "Les pixels ne doivent PAS etre normalises dans le preprocessing "
            "(la couche Rescaling du modele s'en charge)."
        )
        self.assertAlmostEqual(
            float(processed.max()), 255.0, delta=1.0,
            msg="Les pixels blancs doivent valoir ~255 apres preprocessing."
        )

    @unittest.skip("Requiert le vrai modele Keras — executer localement")
    def test_rescaling_layer_present_in_model(self):
        """Verifie que le modele contient bien une couche Rescaling(1/255)."""
        rescaling_layers = [
            l for l in model.layers
            if l.__class__.__name__ == 'Rescaling'
        ]
        self.assertGreater(len(rescaling_layers), 0,
            "Le modele doit contenir au moins une couche Rescaling.")
        scale = rescaling_layers[0].get_config().get('scale', None)
        self.assertAlmostEqual(scale, 1 / 255.0, places=6,
            msg="La couche Rescaling doit avoir scale=1/255.")

    @unittest.skip("Requiert le vrai modele Keras — executer localement")
    def test_no_double_normalization_effect(self):
        """Deux images differentes doivent produire des predictions differentes.
        Predictions identiques = symptome de double normalisation."""
        img1 = Image.open("images_to_test/desert_96.jpg")
        img2 = Image.open("images_to_test/meadow_89.jpg")
        pred1 = model.predict(preprocess_from_pil(img1), verbose=0)
        pred2 = model.predict(preprocess_from_pil(img2), verbose=0)
        self.assertFalse(
            np.allclose(pred1, pred2, atol=1e-3),
            "Predictions identiques = symptome de double normalisation."
        )
\end{minted}
